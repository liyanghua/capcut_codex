# 视频质量、线上反馈与生成过程业务评价体系

> 状态：业务质量范围已确认，已融入抖音电商官方内容基线；阶段北极星映射已补充，评价契约仍待实施
>
> 日期：2026-08-16
>
> 修订日期：2026-08-19
>
> 首版校准场景：电商付费广告
>
> 适用范围：多场景通用评价框架，首版不改变现有 Gate 或生产授权

## 1. 背景与决策

现有参考视频复刻流程已经定义了 Gate、输入哈希、素材证据、配音预算、时间轴和最终技术校验，能够回答“生产过程是否正确执行”。它尚未统一回答三个业务问题：

1. 一条视频在业务上是否高质量；
2. 线上表现是否由视频本身带来，以及结果如何反哺下一轮生成；
3. 生成过程是否以稳定、低返工、低人工成本的方式交付了盈利视频。

本设计采用“分层质量体系”，不把所有信息压缩成单一总分。总体目标为：**以转化和利润为主目标，以内容增长指标作为前置信号，以合规质量和生产经营效率作为约束条件。**

拆解、复刻、脚本、分镜与成片的创作目标、策略候选和阶段评价映射见 [参考视频复刻创作质量升级设计](2026-08-19-reference-remix-creative-quality-upgrade-design.md)。该设计使用本文件的 L0/L1/L2/P 口径，不建立另一套成片总分。

框架支持多场景，但第一版使用电商付费广告校准。当前可获得单视频 `creative_id` 级曝光、点击、成交、退款、商品毛利和广告消耗；投放只能部分受控，因此所有线上结论必须同时声明证据等级。

## 2. 目标与非目标

### 2.1 目标

- 定义成片硬门禁、离线内容质量和线上经营质量；
- 将抖音电商官方优质短视频标准作为首版平台硬基线，内部规则只能更严格、不能更宽松；
- 形成可解释的六维离线质量画像，而不是只输出总分；
- 以退款后的贡献利润衡量实际经营价值；
- 区分受控因果证据、部分受控相关和观察性信号；
- 把线上异常映射为生成阶段的诊断假设；
- 统一五阶段的质量、返工、效率和成本口径；
- 形成“可测试、验证中、可扩量、可沉淀、已淘汰”的业务状态；
- 只沉淀有适用条件和失败边界的组件经验。

### 2.2 非目标

- 不用单个综合分替代 Gate、质量画像和经营结果；
- 不为所有平台、品类和价格带规定统一 CTR、CVR 或 ROI 阈值；
- 不把自然分流结果直接解释为视频造成的增量；
- 不因一次线上跑赢就自动改写生成策略或提升为通用模板；
- 不把内部平台基线通过表述为“抖音官方认证优质”，也不承诺获得平台流量权益；
- 不自动修改已批准产物、历史审批或 `pipeline_state.json`；
- 不降低现有 Gate 1–5、素材证据、声明真实性或技术验收要求；
- 不在本设计中开放普通 V2 生产、共享生产缓存或一线发布。

## 3. 评价对象与身份

视频质量不是 MP4 文件的绝对属性。投放前先创建稳定的 `evaluation_context_id`：

```text
evaluation_context_id
= video_version_id
x product_id
x offer_id
x audience_id
x platform_placement
```

上线后，一个 `evaluation_context_id` 可以绑定一个或多个平台 `creative_id`。线上快照的可比较单元为 `evaluation_context_id × creative_id × delivery_window`；投放前评价不依赖尚不存在的 `creative_id`。

其中：

- `video_version_id` 唯一标识生成版本，并绑定脚本、素材、声音、时间轴和生成配置；
- `creative_id` 唯一标识平台投放实体，并通过不可变映射关联 `evaluation_context_id`；映射载体（投放 API 回填或人工登记表）在首版数据接入验证中冻结；
- 商品、Offer、人群、版位和时间窗口构成线上结果的比较上下文；
- 身份维度（商品、Offer、人群、版位）任一变化即切分为新的 `evaluation_context_id`；出价、预算等投放参数微调不改变身份，同一上下文继续累计，但必须在快照中登记为投放混杂因素；`audience_id` 的判定粒度（人群包 ID 或定向参数集）在首版数据接入验证中冻结；
- 同一 MP4 在不同上下文中形成不同的经营评价；技术事实和部分画面观察可以复用，但涉及人群、Offer、价格心智或落地页预期的 L1 维度必须按上下文重新评价；
- 缺少稳定版本映射时，线上数据只能标记为 `unattributed`，不得回写视频结论。

## 4. 总体评价结构

评价体系分为三个结果层和一个过程层：

| 层级 | 核心问题 | 输出 |
| --- | --- | --- |
| L0 硬门禁 | 能不能投 | `pass` / `fail`、失败原因、返回阶段 |
| L1 内容质量 | 值不值得投 | 六维画像、分项分数、风险和测试建议 |
| L2 经营质量 | 投了是否创造价值 | 漏斗诊断、贡献利润、证据等级和稳定性 |
| P 生成过程 | 是否稳定且经济地交付 | 首次通过、缺陷逃逸、返工、周期、人工和成本 |

L0、L1 和 L2 共同描述视频结果；P 单独描述生产系统。过程效率不能补偿不合格的视频，线上利润也不能豁免合规或声明真实性问题。

每条视频的标准业务结论为：

```text
门禁结果
+ 平台基线结果
+ 六维内容质量画像
+ 线上经营结果
+ 证据等级与数据成熟度
+ 建议动作
```

## 5. L0 硬门禁

以下任一项失败，视频不得进入投放或扩量：

1. **合规与授权**：素材授权、平台政策、敏感内容和必要披露合格；
2. **声明真实性**：商品、价格、优惠、效果和限制条件有批准事实支持；
3. **商品与 Offer 一致性**：画面、口播、字幕、落地页和实际售卖对象一致；
4. **证据闭环**：关键卖点能被已批准画面或其他有效证据支持；
5. **音画技术质量**：比例、分辨率、帧率、音轨、字幕、时间轴和可播放性合格；
6. **生产可追溯性**：版本、素材、脚本和声音可回溯。投放前不要求尚不存在的 `creative_id`；上线映射完整性是独立校验。

L0 输出必须包含失败项、业务影响、最早受影响阶段和可执行修复动作。L0 不计入 L1 分数。L0/L1 评价所需的落地页快照、结构化人群定义和素材授权证据属于评价输入，由投放方或运营在评价前提供并随快照登记版本；输入缺失时对应检查项判定为不通过，不得以缺失为由跳过门禁。

## 6. L1 离线内容质量

L1 使用 100 分制，但业务界面必须展示六维画像和逐项理由，总分只用于同一场景内排序。

| 维度 | 权重 | 评价内容 |
| --- | ---: | --- |
| 抓注意力 | 15 | 第一帧、首句、冲突或利益点能否快速建立观看理由 |
| 信息清晰度 | 15 | 用户能否理解商品、场景、问题和核心表达 |
| 卖点与人群匹配 | 20 | 卖点是否对应目标人群真实需求和当前 Offer |
| 说服与证据强度 | 20 | 声明是否具体、可信，并被画面或事实支持 |
| 节奏与观看体验 | 15 | 镜头、配音、字幕和信息密度是否协调 |
| 品牌与商品一致性 | 15 | 品牌语气、商品形象、价格心智和落地页预期是否一致 |

每个维度采用统一五档锚点：

- `5`：明确且稳定地完成该维度业务任务，无实质风险；
- `4`：完成主要任务，只有轻微问题，不影响测试；
- `3`：基本可用，但存在可定位的改进项；
- `2`：明显削弱业务表达，需要修改后测试；
- `1`：未完成该维度任务或产生误导风险。

维度得分按权重换算。评分必须记录可观察证据和时间点，不能只写主观形容词。首版合格线通过已批准样本校准，不预设跨场景绝对阈值。为控制主观性，首版校准程序必须包含：每档锚点的锚定样本集（标定集）、双人独立评分及信度指标（如 Krippendorff's α）；信度与权重验证未通过前只展示六维画像与分项理由，不用于排序。“评分者分歧过大”的操作定义写入 `content_quality_policy` 的分歧上限（例如同维度分差达到 2 档即触发复核）；复核保留分项理由，不取无解释平均值。

## 7. L2 线上数据反馈

### 7.1 指标分组

线上指标分为三组，承担不同职责：

| 指标组 | 主要指标 | 用途 |
| --- | --- | --- |
| 诊断信号 | 3 秒留存、有效观看率、25/50/75/100% 完播、平均观看时长、CTR | 定位开头、节奏、理解或 CTA 问题 |
| 经营结果 | 支付转化率、订单金额、退款率、商品毛利、广告消耗、贡献利润 | 判断是否创造实际生意价值 |
| 因果证据 | 对照差异、可比条件覆盖、重复投放稳定性、校正后差异 | 判断结论可信程度 |

诊断信号不是最终成功标准。高点击、低支付或高退款的视频不能被标记为优质经营视频。

诊断指标口径首版冻结为：3 秒留存 = 起播用户中观看达到 3 秒的比例；有效观看率 = 起播用户中达到场景定义有效观看阈值的比例（首版默认 3 秒，阈值写入 `online_evaluation_policy`）；25/50/75/100% 完播 = 起播用户中观看达到对应视频进度点的比例；平均观看时长 = 起播用户观看时长均值，以视频总时长为上限；CTR = 有效曝光中的点击比例。平台口径与上述定义不一致时，快照必须记录平台原始口径和换算规则，不能直接跨平台比较。

CTR 受创意整体影响：`creative_id` 通常同时绑定封面和标题，封面变化会污染 CTR 归因。首版将封面版本列为已知混杂因素，CTR 诊断必须同时登记封面版本；未记录封面版本时，CTR 结论只能作为观察性信号。

### 7.2 北极星指标与利润数据字典

首版北极星指标为按曝光标准化的贡献利润（单臂口径，所有投放视频均可计算）。只有随机分流或 owner 批准的准实验才使用“增量每千次曝光贡献利润”作为升级指标；首版不以增量为默认北极星，也不因无法计算增量而阻塞单臂北极星。利润口径先冻结为：

- `provisional_order_margin`：退款窗口关闭前的订单毛利估计，等于已支付订单毛利减已发生退款和策略配置的预期退款准备；缺少有效准备率时状态为 `incomplete`；
- `settled_order_margin`：退款窗口关闭后的已结算订单商品毛利，已经扣除取消、退款和折让；
- `variable_fulfillment_cost`：可归因到订单的履约、支付和平台可变费用；
- `ad_spend`：与 `creative_id` 和评价窗口一致的广告消耗；
- `attribution_model_id`：冻结点击/浏览归因窗口、订单去重、跨渠道归因和订单归属日规则；
- 所有金额使用统一币种、税费口径和结算时区；首版单平台单币种运行，多币种换算规则列入后续场景；跨窗口退款通过调整记录进入新快照。

退款窗口关闭前使用 `provisional_order_margin` 计算 `provisional` 贡献利润；关闭后只使用 `settled_order_margin` 计算 `settled` 贡献利润。单条视频窗口的公式为：

```text
当前成熟度允许的订单商品毛利
- 广告消耗
- 可变履约成本
= 贡献利润
```

不得再次扣除已经反映在 `settled_order_margin` 中的退款。缺少任一必需字段时，贡献利润状态为 `incomplete`。

为消除投放规模差异，所有比较同时报告：

```text
每千次曝光贡献利润 = 贡献利润 / 曝光量 * 1000
```

只有随机分流或 owner 批准的准实验才使用“增量”：

```text
增量每千次曝光贡献利润
= 当前组每千次曝光贡献利润 - 对照组每千次曝光贡献利润
```

部分受控或观察性数据只能报告“校正后估计差异”。若实验分流、准实验假设或不确定性计算不成立，不得使用“增量”或“导致提升”。

### 7.3 数据成熟度

线上评价分三个窗口推进，不使用单一固定天数替代样本成熟度：

1. **早期诊断**：达到场景最低有效曝光量后，判断开头和观看链路；
2. **中期优化**：达到最低有效点击与支付事件量后，判断点击和支付链路；
3. **成熟结算**：退款与履约观察窗口关闭后，结算真实贡献利润。

每个快照必须携带观察起止时间、曝光、点击、支付、退款、归因覆盖率和成熟度状态。未成熟数据可以触发诊断，不得形成最终盈利结论。

### 7.4 证据等级与不确定性

| 等级 | 条件 | 允许结论 |
| --- | --- | --- |
| A 受控对照 | 随机分流，或 owner 批准的准实验；预先冻结分析窗口、主要指标和停止规则 | 报告效应量、不确定区间和实验假设后，可以支持因果判断 |
| B 部分受控 | 主要条件可比，但至少一个重要条件存在偏差并已校正 | 支持较强相关和扩量验证 |
| C 观察性 | 平台自然分流或条件差异较大 | 只用于发现信号和提出假设 |
| D 数据不足 | 版本、曝光、归因、退款或成本链路不完整 | 不进入视频质量结论 |

证据等级由数据条件决定，不能被人工提高。A 级报告必须记录分流方式、样本量、置信水平、效应区间、主要指标、提前停止规则和多重比较处理。B 级至少按商品、Offer、人群、时间、版位和预算分层比较，并展示校正前后结果与残余混杂因素；无法校正的混杂因素必须显式列出。

### 7.5 数据成熟度配置

成熟度阈值由版本化的 `online_evaluation_policy` 管理，至少包含：

```text
policy_id
policy_version
owner
minimum_exposures
minimum_clicks
minimum_payments
refund_observation_window
minimum_attribution_coverage
confidence_level
minimum_effect_margin
sequential_stopping_rule
calibration_status
effective_at
```

缺少有效策略或未达到门槛时，快照标记为 `insufficient_data`，只能触发诊断，不能进入 `validating` 或 `scalable`。

## 8. 业务状态与决策

每个视频版本使用以下业务状态：

```text
pending_evaluation
-> blocked_quality | testable | retired
testable -> blocked_attribution | validating | retired
blocked_attribution -> testable | validating
validating -> blocked_quality | testable | scalable | retired
scalable -> blocked_quality | validating | retired
blocked_quality -> pending_evaluation（仅限审计作废评价证据后的同版本重评）
```

“暂停扩量”“停投”是投放侧动作，由运营执行，不构成业务状态；本状态机只描述评价结论。

状态规则如下：

| 条件 | 动作 |
| --- | --- |
| L0 在投放前或投放后失败 | `blocked_quality`，禁止投放并生成停投工单，返回最早受影响阶段；停投由运营人工执行 |
| 投放前 L0 通过、L1 达到当前策略合格线 | `testable`，允许小流量测试 |
| 投放前 L0 通过、L1 低于当前策略合格线 | 保持 `pending_evaluation`；由 owner 决定新建版本改版或 `retired`，不得直接进入 `testable` |
| 已投放但 `creative_id` 映射缺失 | `blocked_attribution`，不形成线上结论 |
| `creative_id` 映射修复 | 未达到数据门槛则回到 `testable`，达到门槛则进入 `validating` |
| 映射完整且达到早期数据门槛 | `validating`，按策略生成线上快照 |
| 早期观看链路弱 | 保持 `validating`，生成“暂停扩量”投放侧工单和定向改版假设 |
| 利润为正但证据为 C | 保留，安排更可比复测 |
| 利润为正、证据为 B 且重复稳定 | 进入扩量验证 |
| 预先规定的主要指标达到效应线、区间不跨零且证据为 A | `scalable`，并进入人工复核队列 |
| 点击高但利润差 | 只作为钩子研究样本，不提升为优质模板 |
| 利润持续为负或退款异常 | `retired`，回查卖点、证据、人群与预期管理 |

“重复稳定”“持续为负”“退款异常”和 L1 合格线均由当前 `online_evaluation_policy` 或其引用的场景策略定义；缺少规则时不得自动转换。`learned` 是组件经验的独立审核状态，不是视频投放状态，也不出现在本状态机中。L0 缺陷修复若改变视频、脚本、素材或声音，必须创建新的 `video_version_id`，原版本保持 `blocked_quality`（防御性终态）；只有评价证据录入错误时，才允许审计作废旧评价并使该版本回到 `pending_evaluation` 重评。数据回补、窗口成熟或策略版本变化时生成新快照并重算当前投影，保留旧快照及其状态原因。业务状态不替代 `pipeline_state.json` 的生产审批权威，也不能授权跳过任何 Gate。

投放中的视频被标记为 `blocked_quality` 时，评价系统即时生成停投工单并进入 owner 复核队列；首版停投由运营人工执行，评价状态是停投的必要条件而非自动执行。首版未批准准实验时，状态机实际可达集为 `pending_evaluation`、`blocked_quality`、`testable`、`blocked_attribution`、`validating`、`retired`；`scalable` 仅在 owner 批准准实验且证据为 A 时可达，无实验时扩量由人工运营决定，不视为状态机缺陷。

## 9. 生成过程评价

### 9.1 五阶段业务职责

| 阶段 | 业务问题 | 合格产出 |
| --- | --- | --- |
| Performance-proven Video | 参考内容为什么有效 | 有效结构、节奏、钩子和镜头功能被正确识别 |
| Blueprint | 对谁表达什么 | 人群、卖点、证据、CTA 和时长分配明确 |
| Controlled Mutation | 如何借鉴并形成自有内容 | 保留有效机制，完成合规和差异化改写 |
| Retrieval | 素材能否支撑表达 | 每句声明有合格画面证据，无关素材不进入生产 |
| Reconstruction | 能否稳定交付可投放成片 | 音画、字幕、节奏、技术规格和审核状态可用 |

### 9.2 统一过程指标与口径

每个阶段统一记录六类指标，另按任务和阶段汇总一组经营指标：

1. **阶段产出质量**：依据现有 Track C `stage_output_quality_score` rubric 记录分项结果，本设计不新增或覆盖该字段；
2. **一次通过率**：观察窗口内首次提交即获该阶段最终 Gate 批准的任务数 / 该阶段首次提交任务总数；
3. **缺陷逃逸率**：阶段批准后由下游首次发现、且最早可在该阶段修复的缺陷数 / 该阶段批准产出数；
4. **返工强度**：每个任务的 Gate 返回次数、重做片段数和失效下游范围，按任务和阶段分别记录；
5. **交付效率**：机器时间、API 等待、人工操作、人工等待和总周期；
6. **单位成本**：模型、TTS、渲染、人工审核、补素材和失败重试成本；人工审核成本按登记人时 × 场景费率计价，费率和计时方式在实施计划中冻结。

缺陷按“最早可修复阶段”归责：以缺陷根因产物首次产生的阶段为准，且该阶段 rubric 覆盖该项。跨 Gate 阶段以阶段最终批准点为统计时点，但逃逸发现可以后置——例如 Gate 4 生成后或 Gate 5 发现的脚本类缺陷，只要根因产物（脚本、变更契约）产生于 Controlled Mutation，仍计入 Controlled Mutation 的缺陷逃逸，不因发现时间重归责到 Reconstruction；归责争议由阶段 rubric 覆盖范围裁决。Controlled Mutation 和 Reconstruction 横跨多个 Gate，可以保存进行中快照，但只有现有契约规定的阶段最终批准点完成后才进入最终阶段统计：

| 阶段 | 最终统计批准点 |
| --- | --- |
| Performance-proven Video | Gate 1 |
| Blueprint | Gate 2 |
| Controlled Mutation | Gate 4 生成前 |
| Retrieval | Gate 3 选材确认与证据闭环均通过 |
| Reconstruction | Gate 5 |

7. **汇总经营指标**：按任务和阶段汇总：

- Gate 首次通过率；
- 单条视频人工触达分钟数；
- Brief 完整到可投放的总周期；
- 平均 Gate 返回次数；
- 下游缺陷逃逸率；
- 单条 L0/L1 合格视频生产成本；
- 每条盈利视频生产成本；
- 从首个生成版本到盈利版本的平均迭代次数。

“每条盈利视频生产成本”按成熟结算窗口内该 cohort 的全部生产成本 / 贡献利润大于场景策略底线的视频版本数计算；分母为零时标记 `not_applicable`。“平均迭代次数”以同一商品、Offer、人群和创意实验族为观察单位；“创意实验族”指同一商品、Offer、人群下围绕同一创作假设的一组视频版本，其判定规则在实施计划中冻结。质量、效率和成本必须分别展示。缺少计时或成本时标记为 `not_measured`，不得填零。

## 10. 线上结果到生成阶段的归因

线上反馈先形成诊断假设，再进入下一轮对照验证；系统不得直接自动改写脚本或生成配置。

| 线上现象 | 优先检查阶段 | 典型假设 |
| --- | --- | --- |
| 3 秒留存低 | Performance-proven、Blueprint、Reconstruction | 首屏弱、首句慢、产品出现过晚 |
| 完播低 | Blueprint、Controlled Mutation、Reconstruction | 信息顺序、密度、节奏或时长不匹配 |
| 完播高但点击低 | Blueprint、Controlled Mutation | 卖点弱、Offer 不清、CTA 无行动理由 |
| 点击高但支付低 | Blueprint、Retrieval | 承诺与商品、证据、落地页或人群不一致 |
| 支付高但退款高 | Controlled Mutation、Retrieval | 过度承诺、证据不足、预期管理失败 |
| 质量合格但交付成本高 | Retrieval、Reconstruction、Gate 流程 | 素材查找、返工或人工触达过多 |

一次线上异常可以对应多个阶段。下一轮改版应尽量只改变一个主要假设；多变量同时变化时，证据等级不得按单因素实验解释。

## 11. 经验沉淀（后续阶段）

首版只输出带证据的组件候选，不启用自动经验库，也不改变默认生成策略。后续 Track C 和监督运营阶段再审核以下可复用组件：

- 钩子类型与首屏构图；
- 人群问题与卖点顺序；
- 产品证据形式；
- 节奏和镜头功能结构；
- CTA 类型；
- 素材组合；
- 配音与字幕策略。

每个经验组件必须包含：

```text
component_id
component_type
applicable_context
usage_count
online_result
comparison_baseline
evidence_grade
stability
failure_conditions
source_video_versions
```

只有证据 A，或重复稳定的证据 B，才可进入 `learned` 候选。业务 owner 审核后才能用于默认生成策略；证据 C 只进入研究样本库。

## 12. 模块边界与集成契约

评价体系由四个相互独立的业务单元组成：

1. **Offline Quality Assessment**：读取批准成片、审核证据、落地页快照、人群定义和授权证据，输出 L0/L1；不读取线上效果；
2. **Online Performance Snapshot**：读取 `creative_id` 级投放和利润数据，输出成熟度、指标和证据等级；不修改成片评分；
3. **Process Assessment**：读取阶段状态、事件、耗时和成本，输出过程画像；不改变 Gate 状态；
4. **Decision Projection**：组合前三者，输出业务状态、诊断假设和建议动作；不自动审批、投放或改写策略。

四个单元都以 `evaluation_context_id` 关联。每次计算生成不可变 `snapshot_id`，并记录 `event_time`、`processed_at`、`policy_id`、数据源版本和 `idempotency_key`。早期、中期和成熟评价允许使用同一起点的累计窗口；这里的累计窗口是运营快照的观察窗口，不同于 §3 的投放窗口 `delivery_window`，也不同于 A 级实验预注册的分析窗口，三者分别服务于快照划分、身份比较与因果推断，实施时不得混用。退款回补或重算以新 `snapshot_id` 和 `supersedes_snapshot_id` 保存，禁止覆盖旧快照。重复事件按幂等键忽略。当前业务投影只读取最新有效快照，历史快照用于审计和重现。任一单元失败不会伪造其他单元的结果；业务界面必须允许显示部分可用状态。

快照触发方式写入 `online_evaluation_policy`：L0/L1 关键事件（合规、真实性、声明、映射修复、停投相关）触发即时重算，线上表现与过程指标按策略规定周期批处理生成；触发规则缺失时默认批处理，但停投相关事件必须即时。

数据源优先级固定为：结算/财务数据优先于广告平台消耗，广告平台消耗优先于分析平台事件；冲突时生成 `data_conflict` 快照并阻止盈利结论。读取失败按幂等键重试，超过策略规定次数后标记 `source_unavailable`，不以零补齐。

Track C 已规划的 `quality_scorecard.json`、`stage_output_quality_score` 和 `video_quality_score` 继续是五阶段质量评分的权威字段。本设计的六维 L1 命名为 `content_quality_profile`，描述内容及其投放上下文适配，不替换或重新解释现有 `video_quality_score`。两者在业务投影中并列展示，并分别声明 `measurement_status`、`approval_status` 和证据路径。Track C 已规划的 `stage_workflow_maturity_score`/`workflow_maturity_score` 是流程成熟度口径；本设计的 P 层是业务效率与成本口径。两者数据源可以共享，但口径与展示相互独立，不得互相替代或换算。

## 13. 异常与缺失数据

- `creative_id` 无法关联版本：标记 `unattributed`，不进入反馈闭环；
- 曝光或事件量不足：保持当前成熟度，只提供方向性诊断；
- 退款窗口未结束：贡献利润标记为 `provisional`；
- 毛利、履约成本或消耗缺失：证据等级为 D，不计算完整利润；
- 平台归因回补导致结果变化：生成新快照，保留历史版本；
- 商品、Offer、人群或版位中途变化：切分为新的评价上下文；
- 评分者分歧过大：进入复核，保留分项理由，不取无解释平均值；
- 线上结果与离线评分冲突：保留两者，优先生成可验证假设，不回改历史评分；
- 线上表现异常但 L0 失败：先停止投放，利润表现不能豁免硬门禁。

## 14. 阈值与校准

阈值分两级：

### 14.1 全局底线

全局统一管理合规、真实性、证据、技术质量、身份映射和数据完整性。这些规则不随品类和平台降低。

### 14.2 场景基准

CTR、CVR、观看指标、利润和 L1 合格线按以下维度建立基准：

```text
platform
x placement
x product_category
x price_band
x audience
x optimization_goal
```

首版以同商品、同期可比视频的相对提升和历史分位数作为判断依据。只有样本覆盖、稳定性和复核通过后，才发布场景绝对阈值。首版 bootstrap 规则：场景绝对阈值发布前，`online_evaluation_policy` v1 使用保守初始门槛——历史已批准视频回放校准得出的初始分位数或 owner 指定的先验值——并明确标注 `calibration_status=provisional`；达到该门槛只能进入 `validating` 并触发复核，不能直接进入 `scalable`。样本覆盖、稳定性和 owner 复核通过后升级为正式阈值并发布新策略版本。阈值版本必须记录生效时间和适用范围，历史结论不因阈值更新被静默重写。

L1 的场景合格线由版本化的 `content_quality_policy` 管理，至少包含 `policy_id`、`policy_version`、`owner`、六维最低分、总分最低分、评分者分歧上限、复核规则和生效时间。首版 v1 的合格线以已批准样本校准的临时值发布，同样标注 `calibration_status=provisional`，经信度与复核通过后升级。缺少有效策略或分歧超过上限时，L1 状态为 `review_required`，不能自动进入 `testable`。

## 15. 首版业务视图

首版看板只回答五个问题：

1. 哪些视频现在能投；
2. 哪些视频正在创造真实利润；
3. 结论有多可信；
4. 问题最可能出在哪个生成阶段；
5. 下一轮应该保留、修改或淘汰什么。

视频详情按固定顺序展示：

```text
业务状态
-> L0 门禁
-> L1 六维画像
-> L2 漏斗与利润
-> 数据成熟度和证据等级
-> 过程画像
-> 诊断假设和下一步动作
```

## 16. 首版落地范围

第一版只覆盖电商付费广告，要求：

- 单视频 `creative_id` 与 `video_version_id` 稳定关联；
- 接入曝光、观看、点击、支付、退款、毛利、履约成本和广告消耗；
- 完成 L0 与 L1 人工评分 rubric；
- 生成不可变的线上表现快照和证据等级；
- 展示五阶段过程指标；
- 输出诊断假设和人工确认后的建议动作；
- 使用历史已批准视频做回放校准，再进入小流量监督试用；
- 暂不实现自动经验组件库、自动因果校正或自动策略改写。
- 接入版本化的抖音电商官方内容基线策略包，并保存来源与内容指纹。

实施规划前必须先完成首版数据接入验证并产出数据源清单：逐项确认曝光、观看、点击、支付、退款、毛利、履约成本和广告消耗的来源系统、归属粒度和提供方式（广告平台、商家订单、ERP 或财务结算），冻结 `creative_id ↔ video_version_id` 的映射载体（投放 API 回填或人工登记），并定义每个来源缺失时的降级路径（毛利或消耗缺失 → 证据等级 D，映射缺失 → `blocked_attribution`，退款缺失 → `provisional`）；§1 的“当前可获得”必须在该清单中转为可证实的数据接入契约。回放校准使用的历史视频必须声明样本覆盖范围与选择偏差（例如无稳定映射的 V1 视频如何取舍），不得用未声明的便利样本发布阈值。

后续场景必须复用本设计的身份、证据等级和模块边界，只增加场景指标与阈值，不复制一套平行状态机。

## 17. 验收标准

设计进入实施规划前，首版必须可以被以下业务测试验证：

1. 同一视频在不同 Offer 或人群下产生独立线上评价；
2. L0 失败的视频即使利润为正也不能进入 `scalable`；
3. 高点击、低支付的视频不能被标记为经营优质；
4. 退款回补后能够生成新利润快照并保留旧快照；
5. 证据 C 的跑赢视频只能触发复测，不能直接沉淀；
6. 证据 A 的稳定盈利版本可以进入经验候选；
7. 缺少毛利或消耗时不伪造贡献利润；
8. 线上异常能够映射为一个或多个阶段诊断假设；
9. 过程计时缺失时显示 `not_measured`，不显示零；
10. 质量、线上表现和过程效率可以独立更新，互不覆盖；
11. 任何评价或业务状态变化都不能修改现有 Gate 批准；
12. 阈值版本更新后，历史结论仍可按当时版本复现。
13. 抖音平台底线失败或严重技术底线失败时进入 `blocked_quality`；
14. 官方低质内容项触发 `platform_baseline_fail`，不能进入 `testable`；
15. 官方普通项可以进入测试但必须携带优化建议；
16. 内部基线结果不得被展示为抖音官方认证或流量权益承诺。

## 18. 与现有流程的关系

本体系是 Track C 的业务质量定义输入，不替代 Track B 生产后端：

- `pipeline_state.json` 继续是生产状态与审批唯一权威；
- L0 使用现有 Gate 和验证证据，但不能由单项技术检查推定全部通过；
- `stage_metrics.jsonl` 可以作为过程评价输入，但不能反向覆盖 Gate；
- 当前 G-B 配对的候选置信度和技术通过不能冒充 L1/L2 完整评分；
- 在监督运营和发布条件满足前，本设计不改变普通 V2 生产锁。

后续实施计划应先定义评价契约和历史回放校准，再接线上数据与业务投影，最后才建设运营看板和经验沉淀流程。

### 18.1 创作过程阶段北极星映射

创作质量升级使用以下阶段北极星定位生产问题：

| 过程 | 阶段北极星 | 与本体系的关系 |
| --- | --- | --- |
| 拆解 | Gate 1 首轮结构通过率 | 阶段产出质量和返工效率，不是 L1 成片质量 |
| 复刻方案 | 加权创作目标覆盖率 | Blueprint/Mutation 的目标完成度，不是线上转化预测 |
| 脚本 | 脚本首轮业务通过率 | Controlled Mutation 质量与审核效率，受证据硬门禁约束 |
| 分镜与素材 | 分镜意图完成率 | Retrieval/Reconstruction 的动作、证据和一致性完成度 |
| 成片 | L1 内容质量合格率 | 使用本文件六维画像和平台内容基线，L0 必须独立通过 |
| 工作台 | 有效决策时间 | P 层人工效率，缺少活动日志时为 `not_measured` |
| 线上经营 | 每千次曝光贡献利润 | 继续使用 §7.2 的首版最终北极星 |

阶段北极星不能相互换算，也不能覆盖 L0、L1、L2、Track C 质量分或 `pipeline_state.json`。前三秒、连贯性、一致性和高光属于 L1 分项与诊断信号，必须分别展示，不得只留一个综合分。

## 19. 抖音电商官方内容基线

### 19.1 来源与权威关系

首版平台策略包使用抖音电商学习中心官方文章《什么是抖音电商优质短视频？》：

- 来源 URL：<https://school.jinritemai.com/doudian/web/articlev0/aHd3psfsVEY6>
- 页面发布日期：`2022-11-01 18:24:10`
- 发布主体：电商运营团队
- 本次核对日期：`2026-08-17`

该来源是抖音电商场景的最低平台内容基线。内部 L0/L1 可以增加更严格要求，但不能放宽官方明确的安全、技术和低质判定。页面描述的是优质判断标准和相关权益，不是平台审核算法的完整公式；内部评价通过只表示符合当前内部映射，不能宣称获得官方认证或必然得到流量倾斜。

### 19.2 双层阻断

官方规则按性质进入两个层级：

1. **L0 平台与技术硬门禁**：违法违规、虚假宣传、站外引流、违规营销、违禁品或假货等平台底线，以及严重影响信息接收的声画技术问题。失败后状态为 `blocked_quality`，不得投放；
2. **L1 平台内容基线**：未达到违规或严重技术失败，但被官方标准明确描述为低质的内容表现。任一项为 `low` 时，整体为 `platform_baseline_fail`，不得进入 `testable`，修改后重新评价。

官方“普通内容”不阻断测试，但必须输出差距和改进建议。官方“优质内容”信号进入 L1 质量画像，不覆盖经营质量 L2。

### 19.3 规则映射

| 官方判断维度 | 内部位置 | 首版执行规则 |
| --- | --- | --- |
| 平台内容与电商安全底线 | L0 平台安全 | 任一违规或高风险项失败即 `blocked_quality` |
| 声音杂音、爆音、卡顿、音量和稳定性 | L0 技术质量 / L1 声画质量 | 无法清楚接收信息时阻断；轻微问题进入 L1 |
| 普通话、方言及字幕辅助 | L1 信息清晰度 | 方言或其他不便理解表达缺少普通话字幕时为 `low` |
| 画面清晰度 | L0 技术质量 / L1 声画质量 | 低于 1280×720 为技术失败；不低于 1920×1080且无明显画质问题为优质信号 |
| 画面稳定度 | L0 技术质量 / L1 节奏体验 | 不合理抖动或卡顿达到 3 次，或累计达到 3 秒时阻断 |
| 画面整洁度 | L1 品牌与商品一致性 | 主体遮挡超过 30% 为 `low`；不超过 5% 为优质信号 |
| 色彩与曝光 | L1 品牌与商品一致性 | 失真并影响颜色辨别或主体展示时为 `low` |
| 商品、人物和背景形象 | L1 品牌与商品一致性 | 商品陈列、人物状态、背景整洁和人货场协调分别评价 |
| 声画与口型同步 | L0 技术质量 / L1 节奏体验 | 不同步达到 3 次，或累计达到 3 秒时阻断 |
| 出镜主体专业度 | L1 信息清晰度 | 表达条理、语速音量、情绪和形象进入内容画像 |
| 商品决策信息与专业知识 | L1 说服与证据强度 | 必要信息、核心卖点、专业观点及音画配合进入重点分项 |
| 信息可读性 | L1 信息清晰度 | 专业词汇缺少解释、表达难懂或易误解时为 `low` |
| 趣味性与短视频构成 | L1 抓注意力 / 节奏体验 | 图片轮播、素材堆砌或叙事逻辑差时为 `low` |
| 价值观 | L0 平台安全 / L1 内容质量 | 违规或严重不良价值观阻断；一般表达质量进入 L1 |
| 主题、脚本和制作 | L1 抓注意力 / 信息清晰度 | 主题、内容完整度、镜头语言和制作方式分别评价 |
| 场景化与商品卖点 | L1 卖点与人群匹配 | 使用场景、适用人群、人货场匹配和卖点表达进入重点分项 |

页面建议核心卖点通常以 2–3 个为宜，但同时说明数量应随商品特性判断。因此该项只作为诊断建议，不作为固定数量硬门禁；必要商品决策信息是否完整仍按品类策略评价。

### 19.4 分项状态与聚合

每个官方分项使用以下状态：

```text
high
ordinary
low
not_applicable
not_measured
```

聚合顺序固定为：

1. 平台安全底线失败：`blocked_quality`；
2. 严重声画技术底线失败：`blocked_quality`；
3. 任一适用内容项为 `low`：`platform_baseline_fail`，不能进入 `testable`；
4. 无 `low` 但存在 `ordinary`：`platform_baseline_pass_with_gaps`，允许测试并携带优化建议；
5. 全部适用项为 `high`：`internal_official_baseline_high`；
6. 关键适用项为 `not_measured`：`review_required`，不能自动进入测试。

`internal_official_baseline_high` 不是官方认证状态。平台自身预审或权益中心的结果如后续接入，应作为独立外部事实保存，不能由内部状态推导。

### 19.5 策略版本与更新

抖音策略包至少保存：

```text
platform_policy_id
platform_policy_version
source_title
source_url
source_published_at
source_captured_at
source_content_fingerprint
mapping_version
owner
effective_at
```

策略发布前必须重新核对官方来源并生成内容指纹。来源正文或内部映射变化时创建新版本，不覆盖旧版本；历史评价继续绑定原策略包，新任务只使用 owner 审核后生效的新版本。来源暂时不可访问时保留最后一个已审核版本，并显式标记 `source_refresh_status=unavailable`，不得无提示地推断规则未变化。
