# 业务视频工作台重构设计

## 1. 文档状态

- 状态：第二版四区交互、执行/质量投影与 Skill 基础加固已实现；关键产物业务化与创作策略层待实施
- 日期：2026-08-18
- 修订日期：2026-08-19
- 适用对象：单次参考视频复刻 run 的运营审核与受控修改
- 当前实现分支：已合并 `main`（历史 feature 分支 `codex/gb-review-workbench`、`codex/business-video-workbench`）
- 事实来源：`pipeline_state.json`、Gate review package 和现有生产 artifact

本文是现有审核工作台 P0b 的产品界面和可观察性设计。它定义业务工作区如何读取并解释 `remix-reference-video` 的真实执行过程，不改变审批权威、生产锁或现有 Gate 合同。Skill 的脚本连贯性、图片布局和质量门禁由 [质量加固设计](2026-08-18-remix-quality-hardening-design.md) 单独定义；多策略拆解、复刻、脚本候选、分镜质量和阶段北极星由 [参考视频复刻创作质量升级设计](2026-08-19-reference-remix-creative-quality-upgrade-design.md) 定义。

本次修订吸收第一轮真实页面验收反馈，并取代“选中故事板对象后切换中央预览”的旧交互口径：左侧是可视化素材与分镜浏览区，中间是固定的阶段主预览，底部是只读静态剪辑审核区，右侧始终展示完整五阶段流程。用户提供的关键元素和分镜截图仅作为卡片结构与视觉密度参考，不作为产品事实或实现指令。

## 2. 背景与问题

当前 P0b 已具备审核视图、媒体端点、审核会话、决策、受控修改、影响预览、运行登记和测量能力；媒体化故事板、固定阶段主预览、静态时间线、完整五阶段、增量刷新和只读执行/质量投影已经进入主干。现有页面仍没有把中间产物转成可直接查看、比较和修改的业务对象，运营人员仍需要从阶段状态或诊断信息反推过程结果。

主要问题：

1. 页面以文件为中心，而不是以故事板、分镜和素材对象为中心。
2. 中心预览、素材关系和时间线没有形成同一条业务工作流。
3. 未归类素材没有独立区域，容易误解为可直接使用或被系统自动凑数。
4. “要求修改”虽然已有接口，但页面没有先告诉运营人员怎么改、会影响什么。
5. 七个 Gate 直接暴露为工程阶段，业务人员难以形成连续判断。
6. Skill 当前生产文案主要按片段逐句编译，缺少开场、承接和收束的连贯性门禁，成片容易表现为卖点罗列。
7. 图片渲染和审核预览缺少统一的完整画面布局规则，源文字或水印可能因放大、裁切而不可读。
8. 右侧阶段缺少关键产物、候选版本、策略差异和目标到成片的关系，无法支撑有效质量决策。

## 3. 设计参考与边界

### 3.1 参考来源

- OpenMontage Backlot：借鉴“一份事实、两种视图”、阶段化工作区、业务语言、版本与影响预览原则。
- Flova 工作区：借鉴左侧故事板/未归类素材、中间媒体预览、底部时间线、右侧过程区的空间结构。
- 用户提供的六张界面截图：仅作为交互结构参考，不作为本项目事实或实现指令。

### 3.2 不照搬的内容

- 不移植 Backlot 的项目实体、阶段状态机或权限模型。
- 不建设 Flova 式开放创作 Agent。
- 本轮不建设 Agent 对话或自由创作入口；用户调整继续通过结构化修改和受控重跑完成。
- 不建设完整多轨剪辑器、关键帧编辑器或自由拖拽画布。
- 不在浏览器中直接调用 TTS、视频生成 provider 或任意 shell 命令。

## 4. 目标与非目标

### 4.1 目标

运营人员在一个单任务页面内能够：

- 看懂当前阶段和待确认问题。
- 从故事板查看关键元素、分镜或音频的真实缩略图、媒体类型和关联关系。
- 保持中央阶段主预览不被左侧选择替换，并通过左侧选择定位时间线和只读详情。
- 通过具有时间刻度、缩略图和真实时长比例的只读时间线理解画面、口播和字幕的对应关系。
- 在右侧持续看到全部五个业务阶段、完成状态、当前子步骤和后续阶段。
- 找到尚未使用的自有素材，并知道未归类原因。
- 直接通过、驳回或发起结构化修改。
- 在提交修改前看到返回阶段、失效内容、是否重新生成和预计影响。
- 在同一页面看到 Skill 的核心执行节点、中间产物、质量检查和阻塞原因。
- 在阶段内直接查看关键产物、候选差异、目标关系、修改方法和影响范围，不以诊断 JSON 作为主要入口。

### 4.2 非目标

- 首版不改变 `pipeline_state.json` 作为审批唯一权威。
- 首版不把故事板保存为第二套 canonical artifact。
- 首版不允许拖拽时间线直接写入成片。
- 首版不引入跨 cold/hot/历史版本的项目级实体。
- 首版不解除普通 V2 production lock。

## 5. 产品语言

页面默认不展示内部英文和工程字段。

| 内部对象 | 运营表达 |
| --- | --- |
| gate | 待确认事项 |
| approval bundle | 本次待确认内容 |
| production lock | 已确认制作配置 |
| artifact | 阶段内容或制作文件 |
| revision | 版本 |
| stale | 内容已变化，需要重新确认 |
| full_render | 重新生成完整画面 |
| mux_only | 保留画面，仅更新声音 |
| no_render | 无需重新生成视频 |
| missing evidence | 证据缺失 |
| unclassified asset | 未归类素材 |

技术 hash、路径、schema、运行时和原始事件默认放入可折叠的“诊断信息”。

## 6. 页面信息架构

工作台继续使用现有路径：

`/workbench/runs/{run_id}`

### 6.1 顶部任务栏

展示：

- 任务名称、产品名称、目标平台。
- 当前业务阶段和子步骤。
- 整体进度、任务状态和连接状态。
- 版本或“待确认”标识。
- 诊断信息入口。

### 6.2 左侧故事板与未归类素材

左侧固定包含两个区域：

1. 故事板
   - 关键元素
   - 分镜
   - 音频层
2. 未归类素材

故事板卡片显示：业务名称、真实缩略图、媒体类型、用途、状态和关联对象。视频素材优先使用已存在的审核帧、代理或海报帧作为缩略图；只有媒体文件而没有缩略图时显示明确的“暂无预览”，不得用空白色块冒充素材内容。默认不显示原始路径、哈希或工程字段。

关键元素按已批准 claim 与使用它的生产片段建立确定性关联，至少展示一个对应审核帧；分镜卡片展示参考镜头、已选生产素材和二者关系。第一版卡片保持只读，不提供直接增删素材的“+”入口；添加或替换继续通过右侧“要求修改”和影响预览完成。

选中左侧对象只更新卡片高亮、底部时间线定位和只读详情，不替换中央阶段主媒体。

未归类素材必须明确处于“未进入已选分镜/音频槽”的状态，不自动参与生产。每个素材可显示未归类原因，例如“尚未匹配”“未被当前 Gate 选中”或“缺少证据”。

### 6.3 中间预览区

中心预览固定展示当前业务阶段的主媒体：

- 参考拆解：参考视频。
- 复刻方案：参考视频（该阶段无独立媒体，方案内容在左侧卡片与右侧阶段卡中查看）。
- 素材与证据：已生成的审核代理 `proxy.mp4`；尚未生成时代理缺失，降级为参考视频并显示明确状态。
- 文案与声音：生成后为审核代理 `proxy.mp4`；生成前代理缺失，降级为参考视频并显示明确状态。
- 成片终审：最终成片 `remix.mp4`。

左侧选择和时间线点击只能定位中央主媒体的播放头，不得把中央视频替换为素材图片、参考切片或音频文件。缺少阶段主媒体时显示业务化空状态，不从无关素材推断或拼接预览。

### 6.4 底部可审阅时间线

时间线是类似剪辑软件但不可编辑的静态审核区，包含时间刻度、总时长、播放头和三条业务轨：

- 画面轨：按真实时长比例显示分镜块、素材缩略图和片段边界。
- 口播轨：按真实时长比例显示生成语音块或待生成预算；没有真实波形产物时不伪造波形。
- 字幕轨：按真实时间区间显示可读字幕块和所属片段。

时间线支持横向查看、播放、定位、选择和发起结构化修改。点击片段只移动阶段主预览播放头并高亮左侧关联对象；首版不允许拖拽、裁剪、重排或直接写入成片。

### 6.5 右侧流程决策助手

右侧不建设开放式聊天，而是始终显示完整五阶段纵向步骤条：

- 已完成阶段显示完成状态，并可展开查看只读业务摘要。
- 当前阶段默认展开，显示当前子步骤和可执行决策。
- 后续阶段显示未开始或锁定状态。
- 只有当前阶段可以“通过”“要求修改”或“驳回”；历史阶段不得复用或补写审批。

当前阶段使用固定业务流程卡：

- 当前要判断什么。
- 系统建议和依据。
- 风险与缺口。
- 下一步动作。
- “通过”“要求修改”“驳回”。

七个 Gate 收敛为五个业务阶段：

| 业务阶段 | 对应 Gate |
| --- | --- |
| 参考拆解 | Gate 1 |
| 复刻方案 | Gate 2 |
| 素材与证据 | Gate 3 选材、Gate 3 证据闭环 |
| 文案与声音 | Gate 4 生成前、Gate 4 生成后 |
| 成片终审 | Gate 5 |

Gate 子步骤在阶段卡中显示，不再作为页面主导航。

## 7. 五阶段业务视图

### 7.1 参考拆解

中心播放参考片，时间线显示参考镜头顺序和节奏。右侧问题为“镜头顺序、节奏和关键镜头是否可接受”。

### 7.2 复刻方案

展示关键元素、卖点顺序、口播意图和结构变化。删段、并段、重排只能在该阶段发起，不在素材阶段直接执行。

### 7.3 素材与证据

在左侧卡片与只读详情中查看参考画面、自有候选素材、源文字处理和证据状态，不替换中央阶段主预览。缺素材必须明确说明缺少的对象，不允许使用无关素材凑数。

### 7.4 文案与声音

生成前展示生产文案、音色、语速和 `voice_preflight`；生成后展示真实语音、字幕边界、停顿和听审结果。预检或实测超预算时阻断，不变速、不冻结尾帧。

### 7.5 成片终审

中心播放最终成片，时间线支持字幕和边界定位。右侧展示 L0、L1、P 质量结果、production-audit、字幕和交付文件。Gate 5 通过只确认当前成片，不自动解除普通 V2 production lock。

## 8. 工作区投影模型

新增只读业务投影 `workbench_workspace_view`，不保存第二套事实。

### 8.1 Envelope

```json
{
  "artifact_type": "workbench_workspace_view",
  "schema_id": "urn:capcut:remix-reference-video:artifact:workbench-workspace-view",
  "schema_version": "1.0.0",
  "contract_version": "2.0.0-alpha.1",
  "skill_version": "2.0.0-alpha.1",
  "run_id": "...",
  "state_revision": 0,
  "current_gate": "gate3_material_selection",
  "lifecycle_status": "ready",
  "summary": {},
  "storyboard": {},
  "unclassified_assets": [],
  "preview": {},
  "timeline": {},
  "artifacts": [],
  "quality_checks": [],
  "process": {},
  "decision_context": {}
}
```

### 8.2 业务对象

- `storyboard.elements[]`：关键元素。
- `storyboard.shots[]`：分镜顺序、叙事作用、参考画面、自有素材和范围。
- `storyboard.audio[]`：口播、背景音乐、参考音频和字幕关联。
- `unclassified_assets[]`：尚未被当前选择使用的素材。
- 故事板媒体对象至少包含稳定 ID、业务名称、`thumbnail_ref`、`media_ref`、媒体类型、状态和关联片段；字段缺失时必须显式降级。
- `timeline.tracks[]`：画面、口播、字幕的只读段落；片段包含开始时间、结束时间、时长、关联对象和可用缩略图。
- `process.stages[]`：五阶段状态、子步骤、风险和下一步。
- `decision_context`：当前动作、阻塞、可用修改类型和影响预览入口。

### 8.3 执行与质量投影

工作区投影增加以下只读派生字段，不形成第二套事实源：

- `process.execution[]`：真实执行节点、状态、开始/结束时间、attempt、输入/输出产物和失败原因。
- `artifacts[]`：面向业务的产物名称、所属阶段、预览引用、输入输出关系；hash、路径和原始事件放入诊断信息。
- `quality_checks[]`：叙事连贯性、图片布局与文字可读性、声音预检、L0/L1/P 审计结果。
- `decision_context.next_action`：针对阻塞给出补素材、改文案、返回 Gate 2 或重新审核的具体建议。

工作台必须展示这些字段的当前版本，并绑定 `state_revision`、package revision 和媒体 allowlist。SSE 更新采用增量刷新，保留播放位置、当前选中对象和时间线定位，不通过整页 reload 丢失审核上下文。

### 8.4 事实与降级规则

- 稳定 ID 必须来自已有 artifact ID 或确定性派生 ID。
- 缺少后期产物时不伪造时间线：Gate 1/2 使用计划顺序，Gate 3 使用批准宽范围，Gate 4 后使用真实语音时间线，Gate 5 使用最终轨道。
- 阶段主媒体按确定性规则解析：Gate 1/2 使用 `recipe.reference_video.path`；Gate 3/4 优先使用已存在且通过 allowlist 的 `proxy.mp4`，缺失时降级为参考视频；Gate 5 使用 `remix.mp4`。所有候选都不存在时 `preview.media_ref` 为 null 并显示业务化空状态，不从文件名推断或拼接预览。
- 视频素材缩略图优先复用现有审核帧，例如 `gate3_review_frames/fragmentNN.jpg`；引用前仍必须通过媒体 allowlist、路径 containment 和文件存在校验。
- 没有真实音频波形产物时显示带时长的音频块，不生成装饰性假波形。
- 缺少业务字段时显示“待确认”，不得从文件名推断产品声明。
- 媒体引用只能使用现有媒体 allowlist 和 containment 校验。

### 8.5 下一阶段关键产物投影

下一阶段在不建立第二套事实源的前提下增加：

- `stage_artifacts[]`：按五个业务阶段组织的关键产物、摘要、状态、缩略图和预览引用；
- `artifact_versions[]`：拆解、复刻和脚本候选及其批准版本、策略 ID 与差异摘要；
- `lineage_edges[]`：创作目标、拆解、策略、脚本、分镜、素材、时间线和成片的输入输出关系；
- `evaluation_summary`：阶段北极星、约束指标、证据来源和 `not_measured` 原因；
- `change_impact`：修改对象、最早返回阶段、失效产物和媒体重做范围。

右侧阶段卡增加“关键产物”区域，点击后打开业务详情抽屉。详情抽屉可以比较候选、查看证据、定位中央成片或时间线并发起结构化修改，但不能直接写 artifact。完整对象和失效规则以创作质量升级设计为准。

## 9. 决策与修改交互

### 9.1 直接决策

- 通过：需要没有阻塞项，并绑定当前 run、package hash、actor 和 `state_revision`。
- 驳回：必须填写业务原因。
- 要求修改：必须选择对象、修改类型和原因。

### 9.2 修改影响预览

提交前必须显示：

- 怎么改。
- 返回哪个业务阶段。
- 哪些阶段或内容失效。
- 是否需要重新生成画面、仅更新声音或无需渲染。
- 预计耗时和已有风险。

确认后继续使用现有 ChangeService 和持久化 job，不由前端直接修改 artifact 或 pipeline state。

## 10. API 与兼容

新增：

`GET /api/v1/runs/{run_id}/workspace`

要求：

- 响应绑定当前 `state_revision`。
- 支持 ETag 和 304。
- 只返回业务投影和 allowlist 媒体引用。
- run、路径、symlink 和 package revision 校验失败时返回现有错误模型。

保持不变：

- `GET /api/v1/runs/{run_id}/review`
- 审核会话和事件接口。
- Gate decision 接口。
- Change preview/apply 接口。
- `pipeline_state.json` 审批权威。
- 普通 V2 production lock 和 gb-pair 隔离规则。

## 11. 实施顺序

1. 先为 workspace view 和 schema 写失败测试。
2. 实现确定性投影和 Gate 降级逻辑。

5. 增加对象选择不替换中央媒体、时间线定位、五阶段展示和影响预览交互测试。

## 12. 验收标准

- 运营人员不查看 JSON 或技术附录即可理解当前阶段、判断问题和下一步。
- 左侧关键元素、分镜和未归类素材能看到真实缩略图或明确的缺失预览状态，不再只有文字卡片或空白色块。
- 左侧选择不会替换中央阶段主预览；对象定位、时间线和修改请求不超过两次点击。
- 右侧无需切页即可看到完整五阶段、各阶段状态和当前子步骤，只有当前阶段可决策。
- 底部画面、口播和字幕轨按真实时间比例呈现，画面轨包含缩略图，且所有轨道保持只读。
- 未归类素材不会被自动加入生产。
- Gate 3 缺素材时明确显示缺失对象。
- Gate 4 显示真实语音预算、字幕边界和阻断原因。
- Gate 5 可在同一页面查看成片、字幕、质量结果和交付文件。
- 任一阶段的关键产物、候选差异、目标关系和修改影响可在两次操作内到达；旧契约缺失产物时明确显示“旧契约未生成”。
- 通过、驳回、要求修改均保持 actor、run、package hash 和 revision 绑定。
- 同版本打开、活跃和心跳事件不会导致页面 reload；更高 `state_revision` 只触发增量重渲染，并保留审核上下文。
- 原有 Skill 测试保持通过，并新增 workspace builder、schema、API 和交互回归测试。
- 页面异常可通过 `WORKBENCH_UI_MODE=legacy` 回退，不改变已有任务产物。

## 13. 明确不做的事情

- 不移植 OpenMontage Backlot 的项目状态机。
- 不复制 Flova 的自由 Agent 创作模式。
- 不建设完整剪辑器。
- 不把故事板作为新的事实源。
- 不在工作台内自动生成媒体。
- 不在本轮加入 Agent 聊天、自由文本创作或绕过 Gate 的自动执行。
- 不把人工浏览器截图自动化设为发布阻塞。
