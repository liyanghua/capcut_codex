# 审核工作台预览与时间线布局修复设计

日期：2026-08-21  
状态：已确认，待实施

## 1. 问题与证据

审核工作台桌面三栏布局中，中央成片预览覆盖下方审核时间线。1280×720 真实页面测量结果：

- `.main-stage`：`top=68`、`bottom=708`、`height=640`；
- `#preview-stage`：`top=171.9`、`bottom=575.1`；
- `#review-timeline`：`top=538`、`bottom=708`；
- 两者重叠约 `37px`。

根因是 `.main-stage` 使用固定视口高度的 CSS Grid，预览行由 Grid 分配剩余空间；但 `.preview-stage` 同时强制 `height:clamp(280px,56vh,620px)`，实际高度超过其 Grid 行。它因此跨行溢出，覆盖字幕、诊断区和时间线。单纯增加 `margin` 不能解决根因。

## 2. 已选方案

采用“方案 A：同屏约束”。桌面端中央列保持在可用视口内：标题、字幕、诊断、对象详情和时间线按内容占高；成片预览只使用剩余高度，但保留 `280px` 的最低可用高度。预览中的视频和图片继续使用 `object-fit:contain`，不得裁切、放大溢出或改变媒体比例。

低高度视口无法同时满足预览最低可用高度和其他内容时，由中央列整体纵向滚动；任何子元素不得跨越自己的 Grid 行。移动端继续采用自然文档流，不固定整屏高度。

## 3. 布局契约

桌面端：

- `.main-stage` 使用明确的 Grid 行：标题 `auto`、预览 `minmax(280px,1fr)`、字幕 `auto`、诊断 `auto`、可选对象详情 `auto`、时间线 `auto`；当这些行的总高度超过中央列可用高度时，现有 `overflow-y:auto` 必须产生中央列纵向滚动，而不是继续压缩预览；
- `.preview-stage` 必须设置 `height:100%`、`min-height:0`、`max-height:100%`，不得再使用视口高度作为强制自身高度；
- `#preview-media` 及内部媒体必须受预览容器约束；
- Grid `gap` 是区域之间唯一的垂直间隔来源，桌面端保持至少 `10px`；
- 在 1280×720 和 1440×900 桌面视口中，必须满足 `preview.bottom + 10px <= timeline.top`；字幕和诊断位于两者之间时，只会增加实际距离；
- 时间线保持最小高度，不被预览挤压至不可用。

移动端（宽度不超过 820px）：

- `.main-stage` 必须设置 `grid-template-rows:auto`、`height:auto`、`overflow:visible`，完全解除桌面分数行约束；
- `.preview-stage` 必须重置桌面的百分比高度，使用 `height:min(70vh,640px)`、`min-height:280px`、`max-height:640px`、`aspect-ratio:9/16`、`width:auto`、`max-width:100%` 并在中央列水平居中；
- 时间线位于预览、字幕和诊断之后，不使用 sticky 或 fixed 定位。

## 4. 实施边界

只修改工作台布局 CSS 和模板中的冲突高度声明。模板内联块里的视频 `aspect-ratio`、图片 `height:auto` 及双方的 `object-fit:contain` 行为必须保持不变：可以只删除 `.preview-stage` 的内联声明，或将其余媒体规则原样迁移到静态样式表。不得修改媒体选择、播放头、时间线数据、Gate 决策、审批状态或 API。

不采用：

- 单纯增加时间线上边距，因为预览仍会跨 Grid 行；
- 固定底部时间线，因为会引入新的层级和移动端遮挡风险；
- 缩放或裁切成片内容来适应布局。

## 5. 验证

自动化布局契约应按选择器检查：

- `.main-stage` 的预览行是 `minmax(280px,1fr)`；
- `.preview-stage` 不含强制 `56vh` 高度，且具有 `height:100%`、`min-height:0`、`max-height:100%`；
- 桌面 Grid `gap >= 10px`；
- 移动端覆盖规则明确恢复 `grid-template-rows:auto`、自然高度和预览的数值高度上限。

人工浏览器验收使用当前真实 run `gb-cold-1787280937`：

- 1280×720 与 1440×900：预览、字幕/诊断和时间线无重叠，成片完整 contain，右侧流程助手不被遮挡；
- 1280×640：预览保持至少 `280px`，中央列产生纵向滚动，时间线通过该列滚动可达；
- 820px 与 821px 宽：分别验证移动/桌面断点两侧，不出现百分比高度循环或跨行覆盖；
- 390×844：各区按顺序堆叠，横向时间线可滚动，且 `document.scrollWidth <= innerWidth`。

每个桌面视口覆盖以下状态矩阵：诊断关闭/展开、对象详情隐藏/显示、空字幕/两行字幕。浏览器断言读取真实边界矩形，检查 `preview.bottom + 10 <= timeline.top`；低高度滚动态则在滚动到时间线后检查相同条件，并确认时间线可见、横向轨道可滚动且页面本身无横向溢出。

验收只测布局与显示，不提交 Gate 决策、不生成媒体。
